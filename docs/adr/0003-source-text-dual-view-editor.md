# 基于源文本的双视图编辑架构

## 状态

已接受，2026-09-23，用户在第三轮设计访谈中接受技术路线与失败恢复建议，并明确阅读模式允许勾选任务。

## 背景与决定

产品需要 Obsidian 风格实时预览与阅读模式，并在 VSCode 中编辑现存 Markdown 文件。采用 `CustomTextEditorProvider + Webview + CodeMirror 6`，阅读渲染使用 markdown-it，保留原生源码编辑器入口。

以 VSCode `TextDocument` 为权威文本，Webview 负责视图与输入。阅读模式除任务状态切换外只读；任务操作也必须修改同一文档，遵循保存与撤销规则。

外部变更可安全同步时自动同步；无法安全同步时保留未确认输入、暂停写回并提供恢复提示，不能静默覆盖。首版不承诺多个编辑视图同时输入的协同编辑体验。

## 影响与取舍

- 直接修改源文本，避免以整篇富文本重新序列化作为保存路径；仍需验证换行、编码及所有编辑命令对文本的影响。
- 需要自行实现视图与宿主同步、编辑请求确认和冲突恢复。架构选择不代表这些问题已经解决。
- CM6 编辑解析与 markdown-it 阅读渲染存在两套语法路径，必须用同一组样例核对语义。
- 阅读模式包含可写的任务操作，不能简单地把该模式所有消息一律禁止；必须验证目标任务位置和当前文档版本，避免更新错误的任务。
- 表格编辑需要独立的单元格交互与源码映射；不能以整表源码编辑替代已确认的首版交互。
- Webview 不自动继承原生编辑器的全部功能，首版提供已确定的查找和源码入口。
