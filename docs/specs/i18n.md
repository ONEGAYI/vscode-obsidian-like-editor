# 全局 i18n 适配（懒加载语言包 + 字典映射）

本规格确立 Vsidian 的用户可见文字本地化机制：所有界面文案经语言包字典与 `t()` 取词显示，简体中文与英语双语言，语言可在扩展设置页切换。规格与工单于 2026-09-26 经 grilling 共识定稿（Q1–Q8），工单映射见文末。

## 现状盘点（2026-09，行号为当时快照）

全仓无任何 i18n 设施：无 `vscode.l10n`、无 `env.language` 检测，`package.nls` 机制已通但覆盖率 1/43。硬编码用户可见字符串分布：

| 呈现面 | 数量 | 主要位置 |
| --- | --- | --- |
| 编辑器 webview | ≈85–90 条 | `syncController.ts`（31：快捷操作分组、查找控件、冲突横幅、侧栏）、`formatOperations.ts`（21 条工具条 title）、`outline.ts`/`outlineMenu.ts`/`outlineCollapse.ts`（≈20）、`tableControls.ts`（4）、`liveCodeCard.ts`（3）、`liveDecorations.ts`/`liveMath.ts`/`imageResource.ts`/`mermaidRender.ts`（≈6 错误占位） |
| 设置页 webview | ≈40 条 | `settingsPageView.ts`（15）、`keybindingSettings.ts`（23）、`src/shared/settings.ts` 定义 title/description（10）、宿主页面标题（1） |
| 宿主消息 | ≈28 条 | `textEditorProvider.ts` 为主（通知/确认框/QuickPick/链接拦截），另 `settingsService.ts`/`documentSession.ts`/`linkTarget.ts` 少量 |
| manifest | 43 + 2 条 | 42 条 command title 硬编码中文（仅 `table.create` 已走 nls），加 `displayName`/`description` |

既有可搭车基建：设置变更推送链路（`SettingsService.onChange` → `settings.changed` 广播全部 ready 面板）；设置 schema 目前仅支持 boolean，需本规格扩展。

## 两层语言模型

语言解析存在两个独立层次，语义不同，不得混同：

- **manifest 层**（命令面板标题、扩展市场 displayName/description）：由 VSCode 按**宿主显示语言**解析 `package.nls.*.json`，扩展无法运行时切换。本规格只补全覆盖率与生成机制，不承诺随扩展语言设置联动。
- **扩展自有 UI 层**（编辑器 webview、设置页 webview、宿主通知/确认框）：跟随扩展语言设置 `general.language`。

`general.language` 值域 `auto | zh-cn | en`，内部语言代码统一小写（与 nls 文件名惯例对齐）。`auto` 为默认值：`vscode.env.language` 以 `zh` 开头解析为 `zh-cn`，其余（含 `en` 及未适配语言如日语）解析为 `en`。默认 `auto` 使两层语言在多数环境一致。

## 字典架构

- **单一事实源**：`src/shared/locales/`，每语言一个 TS 文件（`en.ts`、`zh-cn.ts`），仅宿主 bundle 静态引入。
- **类型基准与编译期 parity**：`type MessageKey = keyof typeof en`；`zh-cn` 必须为 `Record<MessageKey, string>`，缺键即编译失败。
- **键命名**：点分扁平键，按呈现面分组；`common` 仅收真正跨面复用的通用词（复制、关闭、重置），避免为省文案制造跨面耦合。

| 前缀 | 覆盖 |
| --- | --- |
| `common` | 跨面通用动作词 |
| `format` | 快捷操作工具条 21 条（兼作对应命令 title 的 NLS 生成源） |
| `outline` / `outlineMenu` | 大纲面板与右键菜单 |
| `table` | 表格可见行控件 |
| `codeblock` | 代码块卡片（复制/折叠/展开） |
| `find` | 查找控件 |
| `sidebar` | 右侧栏（收起/展开、快速操作条、打开设置入口） |
| `conflict` | 外部修改冲突横幅 |
| `decor` | 图片/公式/Mermaid 错误占位文案 |
| `settings` / `keybindingSettings` / `setting` | 设置页框架、快捷键分页、各设置项 title/description |
| `host` | 宿主通知、确认框、QuickPick |
| `command` | 仅 manifest 命令 title 使用的键（无 webview 对应者） |

- **取词**：`t(key, params?)`，`{x}` 简单占位插值，不做复数语法（现有 zh/en 文案均可绕开）；运行时回退链：当前包缺键 → en 包 → 键名本身（编译期 parity 已保证两包一致，运行时回退仅作防御）。
- **装配三径同构**：宿主静态 import 后按生效语言装配；webview 从注入数据装配（见下节）；单测直接向 `t()` 注入测试语言包。同一状态模块三条初始化路径，无第四种旁路。

## 懒加载与切换机制

「懒加载」落在 **webview 边界**：webview 产物（`main.js`/`settings.js`）**不打包任何字典字节**，任意时刻 webview 内存中至多持有当前生效语言包，未生效语言永不进入 webview。宿主作为包载体静态持两语言包（Node 端无加载成本，两包合计压缩后约 10–20 KB，可忽略）。

- **首帧注入**：两个 HTML 生成点（`textEditorProvider.ts`、`settingsPage.ts`）在生成时按生效语言注入数据岛 `<script type="application/json" id="vsidian-locale">{"lang":"…","messages":{…}}</script>`——非执行脚本，不受 CSP `script-src` 约束，首帧文案即就绪、永不空窗。同点同步 `<html lang>` 与设置页面板标题。
- **切换换包**：语言变化不走 `settings.changed` 全量快照附带（语言包体积大，随每次设置变更附带是浪费）。`protocol.ts` 登记独立消息 `locale.changed`（host→webview，payload 含新语言代码与完整新语言包）；宿主在 `settings.changed` 中检测到 `general.language` 变化时发送。webview 原子换包后重渲染常驻文本节点（按需创建的控件自然取新词），并同步 `document.documentElement.lang`。
- **立即生效**：切换不要求重载窗口；宿主后续通知本就每次调用时取词，自动生效。

## 语言设置项

- 新设置分区「常规」，键 `general.language`，字符串枚举（值域 `auto | zh-cn | en`），默认 `auto`。
- **schema 扩展**：`SettingDefinition` 增加 `type: 'string'` 与 `enum: readonly string[]` 值域校验（`valueMatchesType`/`isSettingDefinition`/设置页渲染同步扩展）；设置页新增下拉控件。这是设置 schema 的正式扩展，后续 string 类设置复用。
- **选项显示名**：具体语言用**语言自名**且不自译——`简体中文` / `English`；`auto` 档例外，随当前语言翻译（中文「自动」、英文 "Auto"）。
- **设置定义文案键化**（随设置页迁移工单）：`SettingDefinition` 的 `title`/`description` 字段更名为 `titleKey`/`descriptionKey`，语义改为消息键，渲染层经 `t()` 取词——字段更名由编译器强制全仓迁移，注册表不再含用户可见字面量（防回潮扫描才能全绿）。

## manifest NLS 生成

- 构建脚本（`scripts/`）从 TS 字典生成 `package.nls.json` 与 `package.nls.zh-cn.json`，维护「command id → 字典键」映射表：工具条可见的 21 条命令映射到 `format.*` 既有键，其余命令用 `command.*` 键；`displayName`/`description` 一并生成。JSON 不手写，字典是唯一事实源。
- `package.json` 全部 43 条 command title 改为 `%key%` 引用；发布链路（`scripts/release.mjs` 已打包两份 nls 文件）机制不变，仅补覆盖率。

## 防回潮纪律

**AGENTS.md「约定」新增条目原文**（随基础设施工单落档）：

> - **用户可见文字一律 i18n**：所有面向用户的文字（webview 界面、设置页、宿主通知/确认框、package.json command title 与 displayName/description）必须经 `src/shared/locales/` 语言包与 `t()` 字典映射添加，禁止新增硬编码中/英文字面量；两语言包键集由编译期 parity 把关，回潮由 CI 防回潮扫描（源码 CJK 字面量契约测试）拦截。manifest 侧 `package.nls.*.json` 由构建脚本从字典生成，不在 JSON 里手写。

**CI 防回潮扫描**（vitest 契约测试，TypeScript AST 实现）：扫描 `src/webview`、`src/host`、`src/extension.ts`、`src/shared` 的**字符串字面量**，含 CJK 统一表意文字（U+4E00–U+9FFF）即失败。豁免规则：`console.*` 调用参数与 `throw`/`new Error` 参数（开发面文案，范围外）；既有未迁移项以**显式白名单**登记（文件 + 键名），迁移工单逐项清除，白名单清零后仅保留豁免规则。测试 fixture 的 Markdown 文档内容不在扫描范围（`test/` 不扫）。

## 翻译流程与术语

英文文案由 flash 子代理（GLM-5.3-Flash）逐条从中文源翻译产出，直接入 `en.ts` 字典，**免人工校对**（2026-09-26 用户决策）。翻译以文末术语表为唯一术语源，术语不得自造同义变体。文风约定：按钮与动作用祈使动词（Copy、Collapse）；标题与标签名词短语；描述为完整句、句尾句号；句式 sentence case（仅首词与专名大写）。

## 测试策略

- **既有断言改写**：对 UI 文案的精确相等断言改为经 `t()` 取词断言（断言与字典同源，不再复制字面量）。
- **契约测试**：两语言包键集运行时一致（防构建旁路）；代码中 `t('…')` 引用的键全部存在于字典（AST 扫描字面量键）；防回潮扫描（上节）。
- **构建断言**：webview 产物不含字典字节（抽查标志性词条不得出现在 `main.js`/`settings.js`）。
- **语言切换行为断言**：按视觉层断言约定落在**用户可见文本**——集成/浏览器测试切换语言后断言可见文案变化与 `<html lang>` 同步，不断言 DOM 存在性。涉及 webview 输入/光标行为不变更，浏览器套件按既有纪律执行。

## 范围外

- 开发面文案：`console.warn/error`、`throw`/`new Error` 消息（保留中文，扫描豁免）。
- 测试 fixture 的 Markdown 文档内容（用户文档，非 UI）。
- `README.md`/`README.en.md`（已有双语镜像机制）与 `docs/`（面向开发者）。
- VSCode 宿主自身显示语言（本扩展不改变工作台语言）。
- 复数语法、ICU 消息格式、第三语言（机制预留，本轮不实现）。
