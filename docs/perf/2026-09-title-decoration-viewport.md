# 标题装饰切片的视口渲染实测数据（工单 #5）

状态：2026-09-23 实测。**本文为工程门槛实测数据，非官方承诺**；对应规格见 [MVP 性能契约](../specs/mvp.md)，架构约束见 [ADR-0005](../adr/0005-viewport-rendering.md)。

## ## 被测对象

标题实时预览的完整纵向切片：行首 `#` 语法在非活动行渲染为格式化标题（隐藏标记、按层级放大字号），光标所在行显示源码。装饰分两类（依据 CM6 装饰限制，调研记录见工单 #5 的探索笔记 03 §5）：

- **直接装饰**（`src/webview/headings.ts` 的 `headingField`，StateField 常驻 RangeSet）：标题行级样式类（字号/字重改变行高）与 `#` 标记的 replace 隐藏（lineWrapping 下可能改变折行数）——影响块高度，必须整篇构建一次并随事务增量维护，CM6 高度系统才能对视口外行给出正确高度估计
- **间接装饰**（`viewportHeadingPlugin`，ViewPlugin 按 `visibleRanges` 计算）：视口内标题的左缘强调与活动行源码态提示，纯颜色/边框不改高度，视口外不维护

增量策略：键入事务只重扫变更行与选区移动的旧行/新行（`planHeadingRebuild`），既有装饰经 `RangeSet.map` 平移坐标，不重新解析全文；整篇重建仅发生在装载（init）与全文重同步（doc.resync），属性能契约允许的必要初始化。

## 测量方法

- 环境：Windows 11（10.0.26100），VSCode 1.86.2 便携宿主（`--disable-extensions`），扩展以 extensionDevelopmentPath 加载
- 样例：`test/perf/gen-sample.mjs` 生成的同构普通段落样例——每 50 行一个 `## 二级标题`，其余为固定宽度中文段落行；三个体量只差体量本身
- 工具：`test/perf/runPerf.mjs`（启动宿主执行 `test/perf/suite.ts`），逐档打开样例后经 `_test.perfProbe` 钩子驱动 webview 内探针（`src/webview/perfProbe.ts`）
- 输入延迟：50 轮逐字符插入+删除（每字符一个 CM6 事务，与真实键入同构），每轮计时为 dispatch 同步耗时加两个 rAF 的稳定等待（覆盖 CM6 异步测量与视口重算）；探针编辑带 externalSync 注解，不产生写回
- 滚动回收：`scrollIntoView` 在文档 25%/75% 处往返 10 次后回顶，取 DOM 快照对比基线

原始数据：[data/perf-report.json](data/perf-report.json)。

## 结论与解读

- **DOM 有界**：体量增长 100 倍（1 千 → 10 万行），内容 DOM 数保持 77，比值 1.0，满足"增长 10 倍不超过 2 倍"的门槛且无有界例外需要援引。文本模型承载全文（行数与文件一致），视口外不创建 DOM
- **滚动回收**：10 次往返滚动后回顶，DOM 数 76（基线 77，差 1 为末行渲染边界抖动），节点回到基线附近，无累积泄漏
- **输入延迟与体量无关**：三档 avg 16.5–16.6ms、max ≤ 32.4ms。中位数 18.1ms 与 60Hz 帧间隔（16.7ms）同量级——计时包含等待下一帧渲染完成，渲染工作本身在一帧预算内完成；等待 vsync 是测量的量化粒度而非编辑开销
- **键入路径增量生效**：单字符插入的装饰重扫行数恒为 1，与文档体量无关；全量构建仅装载时发生一次（覆盖全部行）
- **输入延迟样本可作长任务替代证据**：全部 150 个样本 < 33ms，未触及 50ms 长任务阈值

## 已知限制

- **长任务直接观测不可用**：VSCode 1.86.2 webview 中 `PerformanceObserver` 的 `longtask` 条目不可观察（`entryTypes` 与单 `type` 两种注册形式均抛错，探针如实返回 null）；以上以输入延迟 max 样本作为替代证据。后续版本宿主可复跑 `node test/perf/runPerf.mjs` 验证
- 输入延迟为探针事务（externalSync 注解）路径，与用户键入的差异仅在不产生宿主写回消息（postMessage 异步，不在渲染关键路径）
- 样例为固定宽度短行的同构段落；超长行、图片密集、超大单表/代码块按规格需另行单独测量（ADR-0005 已注明不以总文档虚拟化掩盖块内成本）
- 装饰行级判定不识别代码围栏内的伪标题（无语法解析，属 #8 完整双模式显示范围）

## 复现

npm run compile        # 或 node esbuild.mjs
node test/perf/runPerf.mjs            # 报告写入 docs/perf/data/perf-report.json
