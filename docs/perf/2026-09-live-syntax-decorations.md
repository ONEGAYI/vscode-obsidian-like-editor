# 语法树驱动装饰与大围栏细分的实测数据（工单 #8）

状态：2026-09-24 实测。**本文为工程门槛实测数据，非官方承诺**；对应规格见 [MVP 性能契约](../specs/mvp.md)，架构约束见 [ADR-0005](../adr/0005-viewport-rendering.md)。

## 被测对象

- **live 视图（编辑路径）**：`src/webview/liveDecorations.ts`——#8 起装饰语义来源由 #5 的行级正则判定换为 `@codemirror/lang-markdown` 的 `markdownLanguage` 解析树（GFM），解析在 StateField 内经 `@lezer` `TreeFragment` 增量驱动（正常键入只重解析变更附近）；装饰重建区间 = 变更行 ∪ 旧树相交装饰节点 ∪ 容器分类差异扩展（围栏开闭/列表吸收等结构编辑按需扩展，正常键入首轮收敛）
- **阅读视图（渲染路径）**：`src/webview/readingBlocks.ts`——markdown-it token 流切块渲染（`html:false` + DOM 纵深净化）；超过 `FENCE_CHUNK_LINES = 60` 行的围栏按行细分为多个挂载块（#7「超大单块」限制的缓解）

## 测量方法

- 环境与方法同 [#5 数据](2026-09-title-decoration-viewport.md) 与 [#7 数据](2026-09-reading-viewport-mount.md)：`node test/perf/runPerf.mjs`，VSCode 1.86.2 便携宿主（`--disable-extensions`），`test/perf/gen-sample.mjs` 同构样例（1千/1万/10万行；10 万行约 3.55 MB）
- 输入延迟：50 轮逐字符插入+删除，每轮含 2×rAF 稳定等待（`perf.probe` 通道）
- 键入重扫行数：`headingStats.lastUpdateScannedLines`（协议字段名沿用 #5，语义为"最近一次事务的装饰重建行数"）
- 大围栏：`generateGiantBlockSample(20_000)`（约 3.55 MB，1 个 2 万行围栏），切换 reading 后的挂载与轮询耗时

原始数据：[data/perf-report.json](data/perf-report.json)。

| 长任务（PerformanceObserver） | 无 | 无 | 无 |

| 初始全量构建行数 | 1001 | 10001 | 100001 |

对照：#5 行级正则判定时期（标题装饰切片）输入 avg 16.1–16.2ms、基线 DOM 75——**语义来源换成解析树后，键入路径成本持平**（+1 基线 DOM 来自标题内容 span；重扫行数保持 1 行，键入不遍历全文的性能契约经真实宿主复测成立）。

### 阅读路径（markdown-it 渲染后）

| 指标 | 1 千块 | 1 万块 | 10 万块 |
| --- | --- | --- | --- |
| 挂载块数（基线 → 10 次往返滚动后） | 45 → 45 | 45 → 45 | 45 → 45 |
| 容器元素数（基线 → 滚动后） | 92 → 92 | 92 → 92 | 92 → 92 |

### 大围栏按行细分（2 万行围栏，3.55 MB 级）

| 指标 | #7（未细分：整块挂载） | #8（60 行/片细分） |
| --- | --- | --- |
| 块模型总数 | 3 | 336 |
| 进入视口挂载块数 | 2（含围栏整体） | 3 |
| 容器元素数 | 4 | 10 |
| 切 reading 模式轮询耗时 | 约 331ms | 108ms |

解读：细分把"进入视口即整体挂载 2 万行"变为"只挂载视口附近的 3 片（每片 ≤ 60 行）"，块内文本布局与测量成本不再随围栏体量一次性发生；轮询耗时含 150ms 粒度的等待噪声，真实挂载成本降幅大于表面数字。窗口行为由契约测试固定（`test/unit/readingBlocks.test.ts` 的细分断言与集成用例「大围栏按行细分」）。

## 结论与解读

- **键入路径与体量无关**：10 万行文档单字符插入的装饰重建行数为 1，输入延迟 avg 16.3ms 与 1 千行（16.2ms）持平——`TreeFragment` 增量解析 + 变更区间重建的策略在真实宿主成立
- **结构编辑按需扩展**：围栏开闭等结构编辑触发容器差异扩展（重建范围可到文末）——集成与单测以「增量 == 全量对拍」固定正确性；此类编辑非正常键入路径，不计入键入契约
- **阅读路径无回归**：挂载/回收/解析次数与 #7 完全一致；DOM 计数变化全部来自语义标签结构（可由片段按标签定位，属 #8 目标而非泄漏）
- **超大单块限制缓解**：围栏类超大块已按行细分；超大**单表**（#12 表格票）与大列表仍为整块挂载——列表通常行数有限，表格待 #12 落地时另行评估是否需要同级细分

## 已知限制

- 结构编辑（输入/删除围栏标记、删除块间空行引发的列表吸收）的重建范围可扩展到受影响容器末尾——正确性优先的保守策略；实测样例中不构成感知延迟
- live 侧语法高亮 token（代码块内高亮）未启用（`language-x` 类已就位），属后续扩展
- 输入延迟含 2×rAF 等待，数值为工程口径（同 #5/#7），非纯 dispatch 成本
