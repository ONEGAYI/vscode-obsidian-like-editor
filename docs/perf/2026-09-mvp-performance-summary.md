# MVP 性能与功能验证汇总

状态：2026-09-24，补测工单 #23、#24。原始数据见 [perf-report.json](data/perf-report.json)。本次数据来自单机单次真实宿主测量，是工程记录，不是对其他机器的延迟承诺。先前 #5、#7、#8、#12 的专项记录保留在本目录；下表数值以本次重跑为准。

## 环境与口径

| 项 | 本次条件 |
| --- | --- |
| 硬件与系统 | AMD Ryzen 7 9700X、47.1 GB 内存、Windows 11 专业版 10.0.26100 |
| 宿主 | VSCode 1.86.2 便携版；隔离 profile、禁用其他扩展，扩展经 extensionDevelopmentPath 加载 |
| 入口 | node test/perf/runPerf.mjs；样例由 test/perf/gen-sample.mjs 生成 |
| 打开计时 | 从 openWith 命令发出分别计到 webview ready、init 后全文模型与内容 DOM 创建、首次探针输入 dispatch 并等待两个 rAF 稳定。第三项使用 webview 内时间戳，是实际编辑路径的可用性代理，含测试命令调度开销；未模拟真实键盘事件 |
| 精度 | 前两项宿主轮询 25 ms；命令派发、测试消息往返和冷启动包含在读数内 |
| 输入与回收 | 同构档每档 50 轮逐字符探针输入、10 次往返滚动；边界形态各 10 轮输入、6 次滚动。探针变更随后还原，不写回文档 |

**样例大小已核对实际 UTF-8 字节数。** 行数档位与文件大小档位分别回答视口有界性、日常文档体量两个问题。当前生成器的 1千/1万/10万行 live 样例分别为 86,753／877,494／8,874,895 字节；旧报告中的 33.6 KB／345 KB／3.55 MB 与当前生成器不符，不再沿用。

## 同构短行与文件大小档位

“打开”两列按 ready→全文装载→首次探针输入完成记录，单位毫秒。“切换”为 live→reading／reading→live。reading 样例与同名 live 样例大小接近，实际字节数在原始报告中逐项记录。

| 档位 | live 字节 | live 打开 | reading 打开 | live 输入均值/最大 | 切换 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1千行 | 86,753 | 195→226→236 | 77→109→117 | 16.6／22.8 | 109／109 |
| 1万行 | 877,494 | 113→175→183 | 108→171→179 | 16.9／28.7 | 108／109 |
| 10万行 | 8,874,895 | 236→660→671 | 228→746→780 | 16.7／21.9 | 356／112 |
| 10 KB 档 | 10,250 | 55→86→104 | 109→109→126 | 14.7／18.9 | 110／109 |
| 100 KB 档 | 102,424 | 75→106→123 | 78→78→94 | 16.1／18.9 | 108／109 |
| 1 MB 档 | 1,048,578 | 90→153→162 | 108→170→195 | 16.1／18.5 | 109／109 |

- **DOM 门槛通过本次复测**：1千/1万/10万行与 100 KB、1 MB 档 live 内容 DOM 基线与回顶均为 75；10 KB 档均为 129。reading 基线与回顶均挂载 45 块、92 个容器元素，全文解析次数为 1。10万行对 1千行的体量增长未使内容 DOM 增长。
- **完整装载时间与 ready 不同**：10万行 live 为 236→660→671 ms，reading 为 228→746→780 ms。只引用 ready 数值会漏掉全文初始化与第一次编辑路径。1千行是本次进程中的首个面板，含冷启动；后续档位共享已加载资源。
- **内存只保留原始采样**：JS 堆取自 renderer 进程级 performance.memory，包含同进程面板与尚未回收的对象，本次未强制 GC。不能把逐档读数解释为单面板净占用，也不能据一次回落断言无内存泄漏。

## 边界形态专项

| 样例 | 结构与大小 | live DOM 基线→回顶 | live 输入均值/最大 | reading 挂载块／DOM 基线→回顶 |
| --- | --- | ---: | ---: | ---: |
| 超长行 | 12 万字符单行 + 120 个短段；362,807 字节 | 9→9 | 18.2／20.0 ms | 2→2 块；6→6 DOM |
| 图片密集 | 240 个图片块、24 个不同尺寸的本地 SVG；7,259 字节正文 | 31→31 | 13.9／18.2 ms | 6→16 块；19→49 DOM |

图片样例在 reading 首屏观察点有 5 张加载成功、0 张报错；挂载块由 6 增至 16，反映图片加载与布局时点会影响读数。本次 live 内容 DOM 基线与回顶均为 31；前一次重跑曾出现 248→31。探针未记录逐张加载的时间点，不能断言峰值与单一原因。该结构不与同构纯文本档位做 2 倍比率比较。图片尺寸变化后的锚点稳定性另有 #7 集成用例。

超长行的 reading 模式仍以整段为挂载单位；少量 DOM 节点不代表该大块的文本布局成本有界。此前 2 万行单围栏按 60 行细分的实测为 336 块模型、首屏挂载 3 块、容器元素 10，见 [大围栏专项](2026-09-live-syntax-decorations.md)。

## 功能验证与剩余边界

本次改动后的单测与真实 1.86.2 宿主集成套件覆盖输入保留、任务、表格、双链、图片、CSS 入口、查找和两种视图的主要语义。用例名与执行结果由 test/integration/suite/cases.ts 输出；这些自动化结果不代替[人工验证清单](../specs/manual-verification.md)的真实 IME、鼠标、日常安装与跨环境操作。

- 图片密集样例复用 24 个 SVG，验证视口挂载与本地图片通道；没有覆盖不同编码格式和大型位图的解码内存。
- 万匹配量级查找的匹配语义有单测，渲染与逐次步进耗时没有专项采样。
- 读数是单机单次，且冷启动顺序固定。换机器或交换档位顺序时需按同一命令重跑。
- Windows 1.86.2 已与 CentOS 7.9 建立 Remote SSH 会话并装入远端 VSIX；中文写回、任务勾选、SVG 显示、模式切换及按名双链单击已取得人工或磁盘证据。其他双链形态、断连恢复及标题修正包的目视结果仍待验，不能由本机性能数据推断通过。
