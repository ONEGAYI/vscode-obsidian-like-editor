# 代码块卡片性能实测（#78–#85）

日期：2026-09-26。测量环境：本机 Windows + VSCode 1.86.2 便携宿主（`node test/perf/runPerf.mjs`，独立桌面）；数据文件 `data/perf-report.json` 同批提交。功能规格见 [code-block-card.md](../specs/code-block-card.md)。

## 结论

- **普通文档无回归**：100k 行档输入延迟 avg 17.2ms，与历史基线一致（卡片功能默认开启下测量）。
- **代码块密集档可接受**：1342 行 / 约 134 张卡片 + 全量高亮，击键 avg 29.4ms / max 33.7ms——约为纯文本档（17ms）与公式/图表档（15.6–16.0ms）的 1.7–1.9 倍，仍低于单帧预算的一半。来源：每次键入触发卡片装饰对围栏表全量重建 + 被编辑块高亮缓存失效重解析（`(语言, 源码)` LRU 命中的未编辑块零成本）。
- **超大围栏降级生效**：6007 行单一围栏（>4096 上限，跳过着色）击键 28.4ms，与密集档相当；着色跳过避免了逐键全块解析。
- **DOM/挂载有界**：codeDense live DOM 349→349（滚动前后不变）；阅读挂载 12→12；模式切换 110–126ms 与其他档持平。

## 体积核查

- `out/webview/main.js` 约 2.4 MB（语言包增量约 1.6 MB——规格预估 0.4–0.5 MB 偏低，Lezer 解析表 minify 后的体积占比高于解包直觉）。
- **VSIX 解压总量 4551 KB**（单文件警告 3 MB 未触线）；原总量警告线 4.5 MB 下余量仅约 57 KB，**用户决策（#85 验收）总量警告/上限各上调 1 MB 至 5.5 / 6.5 MB**——新警告线下余量约 1.06 MB。后续增补语言包或其他资产前仍需核对余量，越过时按规格预案改独立懒加载产物（mermaid 先例）。

## 已知限制

- **超过 4096 行的围栏跳过语法着色**（回退纯文本卡片；卡片/行号/复制/折叠不受影响）：单块逐键全量解析不可接受，Lezer 增量解析接入前以此熔断。6007 行档实测证明降级路径成本与常规档相当。
- **代码块密集文档击键延迟约为纯文本的 1.8 倍**（29 vs 17ms）：卡片装饰对围栏表全量重建按设计取舍（围栏数 × 块行数发射，成本与围栏数线性）；千级围栏文档仍远低于可感阈值，万级围栏文档若出现可感卡顿再引入按块增量。
- 语言徽标为字形徽标（非矢量 logo），见 CHANGELOG 已知限制。

## 附：性能套件存量断裂修复（随 #85）

`test/perf` 套件自 #38（三态视图与全局模式记忆）起即已断裂，与本分支无关，本轮顺带修复：

- `toggleViewMode` 在 #38 起为三态循环（live→reading→**source**），套件原「reading → live 再 toggle」会把面板翻去源码编辑器（会话销毁、等待超时）。改为显式 `mode.toReading` / `mode.toLive` 宿主命令。
- 面板内 `view.mode.set` 不写全局模式记忆——套件若用它切回 live，下一档 `openWith` 会按 restore-reading 异步回放成 reading，与后续操作竞态（10k 档稳定复现的根因）。显式命令由宿主写记忆，竞态消除。
- `runPerf.mjs` 的 `PERF_SIZES` 环境变量被自身 SIZES 覆盖，CLI 过滤无效（未修，保持现状记录）。
